待解決疑問

下列項目會改變研究操作或資料語意；部分已有暫行方案，仍需與指導教授確認後定案。

待研究設計共識
待與教授確認 01

未作答題目的後續處理

目前：Task Judge 已用四種狀態建立診斷結果；任何不是 correct 的題目目前都會依 Task 順序進入後續錯誤佇列。

需決定：unanswered 應維持原順序、排到錯題之後，或不作為 Historical EBL 目標。

影響：決定五分鐘內優先處理 learner 已出現的錯誤，還是先補尚未嘗試的知識缺口。

暫採最小方案 02

Disclosure D0／D1 的資訊邊界

暫行方案：單次 structured completion 可在私有 context 讀取 correct answer、source_text 與 evidence IDs，用來判斷 learner progress；這些資料不代表可對受測者揭露。

可見邊界：D0 不增加新史實；D1 只指出檢查位置。正解提前出現在回覆時，後端拒絕候選內容並重新生成。

保留風險：目前採最低限度字面與固定句型攔截；語意改寫風險以 Prompt 限制、重生與 audit 紀錄管理，不增加第二次 LLM 審查。

暫採最小方案 03

Historical EBL 的完成標準

暫行方案：同一次 LLM structured completion 判斷「核心主張已修正、使用至少一項相關證據／脈絡、能把證據／脈絡連回修正主張或指出原推理遺漏」；三項皆成立才可 RESOLVED。

後端限制：缺任一項卻提出 RESOLVED 時拒絕該候選並重新生成；只答對答案仍算尚未完成。

D4 行為：最高協助後仍未解決時不自動公布答案或跳題；learner 可選擇「處理下一個錯誤」，系統記錄 unresolved_after_max_support，未選則繼續 D4。

暫採 HAT 方向 04

前後測與 Historical Thinking 測量整合

暫行方案：後測採 HAT 式短史料建構題，以同事件的新史料測量證據運用、因果／脈絡推理與歷史觀點；史實知識另外計分。

最低驗證：使用共同 rubric、專家審查、少量 think-aloud 試測與盲評抽樣複評，避免把角色扮演或寫作流暢度誤當成 Historical Thinking。

仍待定案：正式維度、後測時間、每個向度題數與缺漏資料規則仍需和教授確認。

最高優先待與教授確認 05

D4 未解決後的正解公布時點

目前：保留現行流程；D4 仍未解決時不直接公布答案，learner 可繼續互動或主動切換下一個錯誤，並記錄 unresolved_after_max_support。

需決定：標準化正解與訂正說明應在後測前提供，成為 EBL intervention 的一部分；或在後測完成後提供，避免直接答案影響後測結果。

影響：前者較符合「錯誤後需完成訂正」的學習流程；後者較能避免相同知識答案直接污染測量。正式時點必須在收案前由教授確認並固定。

暫定設計共識 06

EBL 與 Historical Thinking 的角色分工

設計共識：EBL 是 02／04 被操弄且主要的互動教學鷹架，流程聚焦 learner error、重新檢視、反思、再次嘗試與自我修正；Role-play 是另一個獨立變項。

共同框架：Historical Thinking 存在於 01–04，用來讓 AI 的歷史回應更重視證據、脈絡與合理因果，但 LLM 不明示要求 learner sourcing、contextualization、corroboration 或 evidence-based argumentation。

待程式對齊：現行 02／04 仍會選擇 Historical Thinking operator，並把證據／脈絡與推理連結納入 RESOLVED；後續應移除這項額外鷹架，確保四組只有 EBL 與 Role-play 兩個操弄差異。
